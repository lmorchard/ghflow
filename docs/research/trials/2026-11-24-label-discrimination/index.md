## Review method

- Every diff was stripped of branch and model hints and relabeled `diff-1` to `diff-6`.
- Every review used the same prompt and criteria: issue body, base commit, anonymized diff, and gate results. The reviewer did not inspect the repository or run tests.
- One reviewer model (`otari-local/claude-opus-5.5`) reviewed all six diffs in separate sessions, one turn each, 42 to 72 seconds each.

## Decision

**Narrow the labels.**

The sample gives no evidence that `impl:local` and `impl:strong` discriminate on implementation quality. Keep them as routing labels for model provider, cost, and privacy. Remove any reading that `impl:strong` predicts a cleaner implementation or needs less review.

The details and the alternative (reclassify) are in the [report](report.md).

## Limits

- Two issues per cell, one epic, one run per arm. Directional evidence only.
- The local arm ran earlier, with different server state, same-model review for #1725/#1726, and an Opus review for #1723/#1731. The trial re-reviewed all diffs under one prompt.
- The strong arm is retrospective and manual. It used the runner's prompt and gates but not the queue runner.
- The reviewer saw only diffs, so a defect that needs surrounding code can be missed or over-weighted.
- No diff was exercised against a live fleet. Manual Verify steps that need hosts were not run.
- The strong sessions saw local branch names and run-narrative links in the issue comments. They did not read the local branches, PRs, or discussion.
- Human calibration of one local and one strong diff was not performed. See the report.
