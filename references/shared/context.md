# Working context and tool output

Keep the information needed for the current operation easy to find. Use these rules to reduce repeated reading during execution without weakening scope, evidence, or required checks.

## Read the selected task

Read the selected task, project instructions, and supplied subject and authorization first. Open a linked reference when its named condition applies, and read the section that owns the decision. A link is a route to relevant instructions, not a request to recursively load every linked document. Keep the task's stopping point and applicable scope limits in view.

For a coordinator, locating a future task reference means confirming its path; read its procedure when that operation becomes relevant. Do not load every future worker procedure before the first dispatch.

If a section depends on another rule, read that rule before acting. Before publication, board updates, review, or merge, read the applicable procedure and its permission and evidence rules. Do not omit a required rule merely to shorten context.

Use [Task notes](task-notes.md) to retain useful facts and decisions. Start with the current summary, then read older entries or their sources when the next action needs them. Reload project instructions or source evidence when they change, rather than repeating unchanged preparation at each checkpoint.

Once the subject, scope, endpoint, applicable rules, and required capabilities are established, dispatch the next authorized operation. If preparation reveals a concrete unmet requirement, report it and continue only work that does not depend on it. Reopen a settled procedural choice only when new evidence or a changed instruction affects it. Uncertainty about a worker's future performance does not by itself change an available dispatch path.

## Search and inspect useful output

Use targeted searches to locate files and symbols, then read relevant excerpts and their callers. Expand the search when the first result does not establish the needed fact. Avoid repeatedly dumping whole files, directories, or logs into the conversation.

When output is long, save the full result in a task-local file when writes are permitted. Inspect enough of it to establish the result, then return the command, outcome, relevant errors, and the saved path. Keep exit status and missing evidence visible. A shortened display does not prove that omitted output contains no error.

For an inventory, paginated API response, or set of checks that must be complete, retrieve and inspect the full result before summarizing it. An output limit is not a task limit. If output was truncated before you could establish completeness, retrieve the missing data before selecting work or reporting success.

## Carry the needed facts forward

For each task or handoff, supply the selected operation, scope and endpoint, worktree, branch and current revision, relevant checks and decisions, notes path, and next action. Link to detailed evidence instead of replaying the entire conversation. Include a known limitation when it affects the next action.

Reuse the responsible worker under [Coordination](coordination.md#handoffs) when its task continues. Keep independent reviewer inputs and required fresh review context within the selected review plan.
