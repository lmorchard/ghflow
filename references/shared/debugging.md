# Debugging unclear failures

Use this method when a failure has more than one plausible cause, or when a correction leaves the same failure without new evidence. An obvious error with a known correction does not need it.

## State a hypothesis

Name one explanation. List the observations that support it and the uncertainty that remains. Do not add edits based on an unsupported assumption.

## Choose one experiment

Choose one small experiment whose result differs between the competing explanations. State what each result would show before you run it. Do not repeat a suite or a command without a new reason.

## Record the result

Record the actual result before you change code, investigate another cause, or report a blocker. A disproved explanation calls for a different explanation or a blocker report, not more edits on the same assumption.

## Report a blocker

When no explanation survives, report the evidence, the attempts, and the remaining uncertainty. Do not extend the investigation beyond the task's limits.

Keep useful attempts in the task notes. Evidence, permissions, and user decisions stay in their existing shared owners.
