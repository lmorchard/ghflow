- If it refuses, I stop and report the current head. I don't mark the new head ready.
- I don't push a notes-only commit.
- If the head did move after review, I name that delta and the commit the review covered.

**Board status:** `board set-status` is only a fallback, for when the PR became ready without `--issue`, `--owner` and `--project`. I won't run it separately, and I won't query the board first.

**Before any write:** I confirm that `identity` reports the configured login as ready. I also confirm that `gh api user` under that identity returns the same login.

**Afterward:** I read the CI and review state with `pr-state` and write the handoff. The handoff covers the `verify-commit` result, the review source and the commit it covers, and the board transition result.
